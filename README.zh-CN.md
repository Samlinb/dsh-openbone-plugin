# OpenBone Studio：在 DSH 中制作骨骼动画

[English](README.md)

通过对话查看和调整骨骼动画，在浏览器中播放预览，再根据效果继续修改。插件已内置 Web Runtime，无需另外下载预览播放器。

## 安装插件

当前 0.4.0 为候选版本，请在 DSH 插件安装界面选择管理员提供的安装包：

```text
dsh-openbone-plugin-0.4.0.tgz
```

安装完成后，重启对应的 DSH profile。也可以使用命令行安装：

```sh
dsh plugin --profile <你的profile> add ./dsh-openbone-plugin-0.4.0.tgz
```

请选择实际运行 DSH 网页版或桌面版的 profile。

## 连接 OpenBone

使用前需要兼容的 DSH、Node.js 24.9 或更新版本，以及管理员提供的 OpenBone 服务地址。自动体验需要 DSH 的持久凭据存储功能；手动账号仍支持 DSH 0.2.1-rc.3 或更新版本（低于 0.3.0）。

### 自动体验

插件内置服务地址为 `https://openbone.dsh.roorobot.com/`。DSH 服务端和浏览器都需要能访问 Honor 所在网络。在“插件 → OpenBone Studio → 配置”中保留此地址和自动试用选项，再检查连接。若使用其他服务，可在配置页填写地址，或在 DSH 服务端设置 `OPENBONE_LIBRARY_URL` 后重启 profile。自动体验时不配置 `OPENBONE_LIBRARY_TOKEN`。第一次使用 OpenBone 工具时，插件会自动领取体验账号并将连接凭据保存在 DSH 凭据库，无需复制密钥到聊天。

同一安装身份重试会继续使用原账号。默认体验 7 天、最多 2 个工程，实际有效期和配额可在工程绑定结果中查看。到期后联系管理员；插件不会自动换号。请保留 DSH 的凭据数据，以便继续访问自己的工程。

### 管理员开通的手动账号

在运行 DSH 的服务器上配置以下环境变量：

| 变量 | 填写内容 |
| --- | --- |
| `OPENBONE_LIBRARY_URL` | 管理员提供的服务地址 |
| `OPENBONE_LIBRARY_TOKEN` | 手动账号的访问密钥；自动体验时不配置 |

如果使用远程 DSH 网页版，应配置服务器端环境。修改连接配置后，重启 DSH。

托管账号地址形如 `https://animation.example.com/u/alice/`，请保留用户路径和末尾 `/`。每位用户使用独立密钥，管理员会提供包含上述两个值的私密 JSON 文件。不要把密钥发到聊天中。

例如，在运行 DSH 的机器使用 PowerShell：

```powershell
$connection = Get-Content -Raw ./my.credentials.json | ConvertFrom-Json
$env:OPENBONE_LIBRARY_URL = $connection.OPENBONE_LIBRARY_URL
$env:OPENBONE_LIBRARY_TOKEN = $connection.OPENBONE_LIBRARY_TOKEN
dsh --profile <你的profile>
```

如果 DSH 由系统服务启动，请由管理员将这两个变量配置到服务环境中。

## 开始制作

在启用插件的聊天中，先让 DSH 连接工程：

> 列出可用的 OpenBone 工程，并把当前聊天连接到我要修改的角色。

新开通的托管账号包含一个空白 `starter` 工程。可以让 DSH 连接它并创建骨骼和动画，也可以指定名称新建空白工程；托管服务会自动启动编辑。参考库初始为空，需由管理员导入选定参考。

从零制作角色时，先让 DSH 执行 OpenBone 创作准备检查，一次查看工程、已有素材、参考库和生图能力。服务配置图片模型后，助手可以生成统一风格的角色分件图，查看实际图片，用素材 ID 创建附件，再制作动画。先检查静态组装，确认关节、比例和视角，再调整动作。如果生图不可用，助手会直接说明需要管理员配置的能力。

> 创建一个原创的蹦跳兔子。先检查工程，生成缺少的身体分件贴图，查看组装后的绑定，制作动画，展示实际播放并保存。

图片任务会在重连后保留。超时后继续查询同一任务，不要重复提交；提交结果未知时需要管理员先核对。生成图片和 PNG 自动检查通过，仍不代表作品质量或用户认可。

接着查看已有动画：

> 这个工程有哪些动画？先帮我看一下行走动作。

提出具体的修改需求：

> 把行走动画的手臂摆动幅度稍微减小，然后生成预览。

也可以从动作参考开始：

> 找一个适合小短腿角色的行走参考，帮我基于它创建新工程。

托管服务会自动启动从参考创建的工程。旧式固定端点服务若返回 `connected: false`，需联系管理员配置该工程后再连接。

## 查看动画预览

让 DSH 生成预览后，打开返回的链接。可以在 DSH 浏览器或自己的浏览器中观看。

播放器支持：

- 切换动画和皮肤。
- 播放、暂停、循环和调速。
- 拖动时间轴、适应画面。
- 保存 PNG 截图。
- 切换中英文界面。
- 选择 OpenBone 或 Spine WebGL 播放方式。

Spine WebGL 的使用遵循随包附带的许可说明。

再次修改动画后，请让 DSH 生成新的预览；已经打开的预览不会自动更新。链接失效时，重新生成即可。

## 反馈、撤销和保存

根据看到的效果继续反馈：

> 落地还是有点生硬，把结束前身体旋转的变化放缓，再让我看一下。

需要还原时：

> 撤销上一次修改，重新生成预览。

确认效果后：

> 保存当前 OpenBone 工程。

服务重启前请先保存工作。每个聊天可以连接一个工程；需要切换时，让 DSH 列出可用工程并更换连接。

托管服务重启后自动恢复最后保存的工程。继续修改前先重新读取当前状态；撤销历史和旧预览链接不跨服务重启保留。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 安装后没有可用工具 | 重启安装插件时使用的同一个 DSH profile。 |
| 无法连接服务 | 请管理员检查服务地址、访问密钥和服务运行状态。 |
| 没有可用工程 | 请管理员将工程设为可用，再让 DSH 重新列出工程。 |
| 预览仍然是修改前的效果 | 在修改完成后请求生成新的预览。 |
| 预览链接失效 | 让 DSH 重新生成预览。 |
| 修改或保存提示冲突 | 让 DSH 重新读取当前工程状态，再继续操作。 |

插件内置的是预览播放器；编辑和保存工程仍需连接 OpenBone 服务。

服务管理员请参阅[托管部署与用户开通](../openbone-service/deploy/README.zh-CN.md)。

## 专业素材生产

使用 openbone_production 管理实际状态：status → plan → concept 或 import-reference → reference → generate-part → adopt-part → review-static → review-motion。每次变更携带 expectedVersion 和稳定 requestId；重试不会重新提交付费任务。

计划记录完整外观、最终动作、视角、关节与层级，每个部件记录父级、重叠要求、轴点和绘制顺序。参考图可由整角色生成或 PNG Base64 导入（最多 1,500,000 字符）；当前还没有拖放上传界面。选择角色参考后，单部件生成会把参考图真实发送给支持参考输入的 Qwen 模型。修复时再附上该部件旧图，只生成候选，不自动替换。检查后 adopt-part 仅替换指定部件；其他合格部件继续复用，旧版本可重新选回。

静态验收必须引用服务端捕获的当前工程截图，逐项记录一致性、重叠、遮挡、边缘和轴点；通过前禁止新增动画关键帧。动作验收检查姿势、接触和循环，需首尾及中间帧证据。换图或改绑定会使后续验收失效。验收记录是助手观察，不等同于用户认可，也不能自动证明美术质量。

现有去绿底适用于非绿色角色分件，并不是通用抠图。参考导入保留原始颜色；含绿色材质时需换分件/抠图方法，不能直接套用去绿底。完整调用字段见随插件打包的 public/authoring.md。


### 三步创作
1. 角色图：生成或导入用户图片，展示并磨合，满意后确认。无需先完成分件计划。
2. 拆图与组装：规划并制作部件，实际装回编辑器，展示真实预览，确认图层顺序和关节拼接后进入动作。
3. 动作：制作、播放、检查关键姿势和循环，反复调整。
每步支持 revisit 返回修改，保留可复用素材，并使下游验收失效；同角色重新分件不再清空合格部件。用户满意通过对话确认，技术验收不等同于用户批准。

### 主界面工作台
点击侧栏 OpenBone 进入三步工作台。开始创作后，输入角色提示词生成图片，或上传不超过 1.1 MB 的 PNG；选择并确认角色图。第二步由创作助手检查角色能否拆分，制作部件并实际组装，页面显示检查意见、图层和轴点，以及真实工程预览。检查通过且预览加载后，点击“确认组装，下一步生成动作”。可提交修改意见、返回前一步或打开创作对话查看进度。工作台独立工程和会话会保留，关闭页面不取消已开始的任务。生图或拆图失败会显示问题，不能直接跳过验收。

角色检查只判断能否识别明确的角色主体。多只兔子可选一只，缺少耳朵或四肢可补全；页面显示选定主体及待修复事项。没有角色主体的图片（如纯山水画）才会拦截。


### 轮廓拆图与局部修正
第 2 步支持沿原图轮廓提取部件、Shift 点击轴点、拖动轮廓点，并按原坐标自动组装保存。选择部件后可圈出局部补画范围，服务端只合成范围内像素，保留其他部件和旧版本；通过“复用部件版本”恢复已有版本，再点击“原位组装并保存”。播放器实际完成渲染后才能确认进入动作步骤。

自动创作由模型识别轮廓并批量提交，界面提供修正入口；当前没有安装通用语义分割模型。复杂毛发、遮挡和缺失部分仍可能需要调整轮廓或局部补画。

## Codex 插件

OpenBone Studio 同时提供独立的本地 Codex 插件。在源码目录运行 `npm run pack:codex`，生成的压缩包位于 `release-codex/`。DSH npm 包和 Codex 包共用工具定义及 OpenBone 服务，分别提供宿主适配层。需要 Node.js 24.9 或更新版本，以及管理员提供的现有 OpenBone 账号。

新建 `~/.openbone/codex.json`，内容为 `{"serviceUrl":"https://your-account.example/","accessToken":"YOUR_ACCOUNT_KEY"}`，替换为管理员提供的完整账号地址和密钥。限制该文件仅供当前操作系统用户访问，不要把密钥发到聊天或放进插件包。适配器也支持 `OPENBONE_LIBRARY_URL` 和 `OPENBONE_LIBRARY_TOKEN` 环境变量，但 Codex 可能不会将自定义环境变量传给插件进程。目前自动试用开通和嵌入式 Studio 界面仅适用于 DSH；Codex 可使用服务生成的预览链接和截图工具。

构建后依次执行 `codex plugin marketplace add ./release-codex/marketplace-v2` 和 `codex plugin add openbone-studio@openbone-local`，然后重启 Codex。在启用 OpenBone 的对话中开始创作。每个独立任务使用不同的小写工作区标识（字母、数字和连字符），继续任务时沿用原标识。同一账号下的工作区并非访问控制边界；适配器无法自动获得 Codex 聊天 ID，在两个对话中使用同一标识会共用工程绑定。
